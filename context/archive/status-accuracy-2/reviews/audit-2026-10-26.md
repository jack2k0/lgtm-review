# Independent ground-truth status audit (2026-10-26)

Re-run of the audit of 2026-10-23 with rebuilt, committed scripts (`scripts/audit/truth.py`, `compare.mjs`, README there). Tool = the built CLI of
worktree `lgtm-review-audit-truth` (branch base `affd6cc`, `--list --json --no-worktrees`, empty archive dir). Truth = derived from the raw JSONL and
the PRD rules only (FR-002, FR-015, S-11, S-16, S-20, background checks, subagents, forks); no code of `packages/core` was read. Counts and
category names only: no prompt text, commands, paths or secrets.

## Verdict

**The >= 97% target is not met, and the 2026-10-23 numbers are not reproduced: 68.3% status match overall (B), 74.0% without subagent activity
(A), 45.5% with Agent calls (C).** The gap is not a regression in the old detection but a different measuring stick plus a new population:
the PRD v0.3 rules (documentation and scratch edits, git-only edits never move the status) that the 2026-10-23 truth did not have, applied to a
population that is now dominated by orchestration sessions that write documentation and run git operations through long Bash commands (python
heredocs, `sed -i` on Markdown next to `git mv`/`git merge`). The two largest categories (below) were confirmed on synthetic probes, not only on logs.

## Population

- 5 project directories, 35 session files, 1 excluded (modified in the last 30 minutes: this session), 34 analysed; 152 subagent transcripts
  attached to their spawning prompt (1 unattached, no spawning tool call found).
- Truth: 168 prompts. Tool: 174 rows, 10 of them in the excluded session, 164 rows joined (B). 4 truth turns with no activity at all (slash
  commands) are absent from the tool and ignored; 0 truth prompts with activity are missing; 0 tool rows without a truth row.
- B = 164 rows / 149 unique uuid (15 fork/resume duplicates, exactly the tool's `inheritedFrom` rows). A (no Agent/Task call) = 131 rows / 116 unique.
  C (Agent/Task call) = 33 rows / 33 unique. A unique-uuid prompt is counted in the session that first contains its uuid.

## Method notes

- Prompts: real user messages; slash-command turns are prompts (except `/clear`, `/exit`, `/compact`); a prompt owns every action up to the next
  prompt, including task-notification turns. Failed Edit/Write calls are not edits.
- Checks: broad classifier on the segment head (after env assignments, `time`, `timeout`, `uv run`, `npx`, `pnpm exec` ...): test runners,
  typecheck, lint, build, package-manager scripts (`pnpm test|check|lint|typecheck|build|ci ...`, `pnpm vitest`), check scripts
  (`check*.sh`, `verify*.sh`, `gate*.mjs` ...), `gh run watch`, `gh pr checks`; `bash -n`, `--help`, `--dry-run` are not checks.
- Exit: `is_error` / `Exit code N`; a masked exit (pipe, `;`, `||` after the check) with exit 0 counts as failing only on failure text
  (`N failed`, `FAILED`, `exit=N`, `BUILD FAILURE` ...). Background checks: the exit code in the task notification (`tool-use-id`).
- Order: position of the tool result in the file; inside one Bash command the segment index; subagent events after the last parent event whose
  timestamp is not later.
- Self-test: 27 synthetic prompts (checked/unchecked/failing/no-changes, masked exits, background checks, in-command order, git operations,
  doc/scratch, slash turn, subagent, fork copy) reproduce their expected truth. The same synthetic session run through the CLI agrees on
  23 of 27 statuses; the 4 differences are the cases that probe the first two categories above (heredoc write to a `.md` file, `git mv` next to
  `sed -i` on a `.md` file, and the same two after a passing check). A separate synthetic probe showed `flock <lock> ./scripts/check.sh` is not
  recognised as a check by the CLI.

## Caveats

- Small, atypical population: two orchestration-heavy repos dominate; 15 of 34 sessions carry the disagreements and many disagreements share
  one command shape, so the effective sample is much smaller than 164 and the intervals are wide (A: 97/131, roughly +-8 pp).
- The truth is mine: the doc/scratch/git classification of shell writes is heuristic (literal paths in heredocs and one-liners, `cd` tracking,
  `$VAR` expansion from assignments in the same command, unresolved variables count as scratch only when the command works under a scratch root).
  `*.log`, `*.patch`, `*.diff`, `*.tmp`, `*.bak` writes count as scratch. A wrong guess moves single prompts, not the big categories.
- Failure evidence for masked exits can be a false positive for mutation probes that print `FAILED` lines on purpose; the earlier audit checked
  such prompts by hand, this one did not.
- The `main` truth follows the PRD wording (file-level git rule); the command-level variant is shown because the previous audits used it.
- No JS/TS-only project: `pnpm`/`vitest` patterns are exercised by this repo's own sessions only.
- The numbers use the CLI of this worktree (main at `affd6cc`); main has moved on since.
