# S-08 llm-titles: opt-in local LLM titles (loopback only)

## Overview

FR-020 / roadmap S-08. Owner decisions of 2026-10-27 (PRD Open Question 6): (a) opt-in only; (b) only an OpenAI-compatible model server on the loopback interface (Ollama, llama.cpp server, LM Studio), no `claude -p`, no remote host; (c) no default model (the user names one), and generated titles never appear in `--summary`, `--export`, `--list`/`--json` or any status, reason or hint.

The user runs `lgtm-review --llm-url http://127.0.0.1:11434 --llm-model qwen3:4b`. The web UI shows, next to each prompt's text, a one-sentence past-tense title marked "generated". Titles are generated lazily in the server, one request at a time, from a condensed and redacted view of the prompt's steps, and cached on disk by input hash, so the same session shows the same titles on every run. Without the flags nothing changes and no connection is made.

## Desired End State

- `--llm-url <url>` and `--llm-model <name>` (both or neither; otherwise exit 1 with a message). Only in server mode: combined with `--list`, `--json`, `--summary`, `--export` or `--archive` -> exit 1 with a message. Optional `--llm-cache-dir <dir>` (default `~/.lgtm-review/cache/titles`; only valid with `--llm-url`).
- URL rule (`parseLlmUrl`): scheme `http:` only; no username/password; host is a literal IPv4 in `127.0.0.0/8`, `[::1]`, or `localhost` (normalised to `127.0.0.1`, never resolved through DNS); any other host -> exit 1 "only a loopback model server is allowed". The endpoint is `<origin><path>/v1/chat/completions` unless the path already ends with `/chat/completions`; query and fragment are rejected.
- At startup (server mode) one stderr line: `LLM titles: condensed, redacted prompt actions go to <url> (model <name>); cache <dir>`.
- Request: `POST` JSON OpenAI chat body `{model, messages:[{role:"system",…},{role:"user",content:<input>}], temperature:0, max_tokens:60, stream:false}`; `fetch` with `redirect:"error"`, timeout 60 s (AbortSignal), response body read up to 64 KiB (larger -> error). Title = `choices[0].message.content` through `sanitizeTitle`.
- Input (`condenseForTitle`, core, pure): prompt text (already ≤ 200 chars), then up to 25 step titles, then up to 20 changed file paths (repo-relative when possible), joined with newlines, cut to 2000 chars, then passed through `redact()`; nothing else from the session (no tool output, no diff content).
- `sanitizeTitle(raw)`: drop `<think>…</think>` blocks, take the first non-empty line, strip surrounding quotes, leading `Title:`/`#`/`*`/`-`, markdown emphasis and backticks, collapse whitespace, remove control characters, cut to 120 chars at a word boundary (add `…`); empty -> `null` (no title).
- Cache: key = sha256 hex of `TITLE_PROMPT_VERSION \0 model \0 input`; file `<dir>/<key[0..2]>/<key>.json` holding `{"v":1,"title":"…"}`; directories created mode 0700, files 0600, atomic write (temp + rename). A corrupt or unreadable cache file is ignored (regenerate). Cache hits need no server.
- Generator in the CLI process: queue with concurrency 1, de-duplicated by key, at most 500 requests per run; after 3 consecutive failures it stops and records one generic error ("model server not reachable" / "model server returned an error"), never the response body.
- API: `GET /api/sessions/:id/titles` -> `LlmTitlesResponse` `{ enabled: boolean, titles: Record<string, string> /* prompt index -> title */, pending: number, error: string | null }`. Without the flags: `{enabled:false, titles:{}, pending:0, error:null}` and no other work. With them: cached titles for the session's own (not inherited) prompts, missing ones enqueued, `pending` = enqueued for this session. Same token/Host/Origin rules as every API route; ETag over the JSON body hash.
- Web: `fetchTitles`; `PromptTable` asks once per session, then every 3 s while `pending > 0` (stops when 0, when the session changes or when live updates are paused). When a title exists it is shown above the prompt text in the row, with a small `generated` label (`title` attribute: "Generated by the local model; may be wrong"). `enabled:false` -> nothing rendered and no polling. `error` -> one muted line under the table.
- Never: titles in `--summary`, `--export`, `--list`, `--json`, statuses, reasons, hints, step titles; no network call without the flags; no call to a non-loopback host; no new dependency (Node `fetch`, `node:crypto`).

## What We're NOT Doing

- No `claude -p`, no Anthropic SDK, no remote/hosted backends, no default model, no auto-detection of a running server.
- No step titles or captions from the model (prompt titles only). No streaming. No cache eviction (document the directory in the README).
- No change to statuses, reasons, hints, summary, export.

## Amendments after plan review (binding; they override the sections above where they differ)

From OpenCode (GLM-5.3-Flash), all accepted:
- A1 (URL): path ending in `/v1` (as the last segment) appends only `/chat/completions`; `http://localhost:1234/v1` -> `http://127.0.0.1:1234/v1/chat/completions` (test).
- A2 (route cost): the `/titles` route does NOT build `PromptDetail`s. It returns cached titles it already knows for the session plus enqueues `(sessionId, promptIndex)` for own prompts not yet known (in-flight set de-duplicates); the queue worker builds the input via the existing cached `detailFor` path, computes the key, checks the disk cache, and only then calls the server. The titler keeps an in-memory map `sessionId -> index -> title` filled from disk hits and responses. ETag over `<project stamp>\0<titles produced count>\0<pending>\0<error>` checked with `notModifiedEarly` before building the body.
- A3 (drain): on 3 consecutive failures or the 500-request cap the queue is drained (`pending` 0) and `error` set to the generic message; the web stops polling when `pending` is 0 OR `error` is non-null.
- A4 (redact options): `condenseForTitle` passes the same redact options `playRoute`/export use (repo dir realpath, OS user name) and makes file paths repo-relative; an absolute path never appears in the input (test).
- A5 (cache dir): `--llm-cache-dir` is rejected when it is inside `--dir`, inside the projects dir or inside the archive dir (reuse the `unsafeArchiveDir` idea); the temp file is opened with mode 0600 before the rename; both shard levels are created with `mkdir(..., { mode: 0o700 })`.
- A6 (loopback edges): every IPv6 form other than `[::1]` is rejected (`[::ffff:127.0.0.1]`, `[::1%251]`, `[0:0:0:0:0:0:0:1]` may be accepted only if normalised to `::1` by WHATWG URL — test what `new URL` gives and decide by the normalised host); the request always goes to the normalised literal host (`localhost` is never resolved; test that the fake server receives the request when started on 127.0.0.1 and the flag says `localhost`).
- A7 (phase split): Phase 2 becomes 2a (flags, incompatibilities, startup line, `parseLlmUrl`, cache-dir checks, endpoint construction, CLI arg tests) and 2b (`createTitler`, cache, queue, `/titles` route, `api.titles.test.ts`, the no-flags spy test and the summary/export byte-identity test). Extra 2b test: a 200 response with valid JSON that is not OpenAI-shaped counts as a failure and its text never appears in `error`.
- A8: unknown session id on `/titles` -> 404 like other id routes (test). README: `--no-titles` has no effect on LLM titles; they never reach summary/export.
- A9: drop `stats()`.

From Grok (grok-4.7), accepted; where they conflict with A1-A9 these win:
- B1 (key needs the detail): on the first `/titles` GET for a session (and whenever the session's stamp changed), the route enqueues every own prompt; the queue worker builds the input from the memoised `detailFor`, computes the key, serves a disk-cache hit without any request, otherwise calls the server. The route itself never builds details (A2 stays for that part).
- B2 (no ETag): `/titles` has NO ETag and never answers 304; always 200 with `no-store` (`sendJson` without etag). Replaces the ETag part of A2.
- B3 (loopback, canonical): decide on `new URL(s).hostname` after WHATWG canonicalisation; allow only a dotted IPv4 whose first octet is 127, or `[::1]`; exact `localhost` is rewritten to `127.0.0.1`; reject everything else including `localhost.`, `foo.localhost`, `0`, `0.0.0.0`, IPv4-mapped IPv6. Tests: `http://2130706433`, `http://0x7f000001`, `http://0177.0.0.1`, `http://127.1` (all canonicalise to 127.0.0.1 -> accepted, request goes to the canonical host), `http://[0::1]` -> `[::1]` accepted, `http://0`, `http://localhost.`, `http://foo.localhost`, `http://[::ffff:169.254.169.254]` rejected. The request must not go through an env proxy (`NODE_USE_ENV_PROXY`/`HTTP_PROXY`): use `node:http` `request` with no agent proxying (or an explicit plain `http.Agent`) instead of global `fetch`, still `redirect`-free (a 3xx is an error), 60 s timeout, 64 KiB cap. Test: with `HTTP_PROXY=http://127.0.0.1:<other port>` set, the request still reaches the model server.
- B4 (endpoint): empty or `/` -> `/v1/chat/completions`; `/v1` or `/v1/` -> `/v1/chat/completions`; a path ending in `/chat/completions` is used as-is; any other path, query or fragment -> exit 1. (Replaces A1.)
- B5 (redaction order): `condenseForTitle` takes `RedactOptions` (repoDir, usernames) from the caller; redact each field separately, join, then cut at 2000 chars on a newline boundary (drop a partial last line); only `.text` is sent. The sanitised title is passed through `redact` again before it is cached or returned. No quotes, excerpts, action outputs or diffs are sent; neither request nor response body is logged.
- B6 (cache safety): refuse a symlink at the cache root or a shard dir (`lstat`), `realpath` and require every file to stay under the cache root, create files with flag `wx` (temp) then rename, `chmod` 0700 dirs / 0600 files after creation; read at most 1 KiB and accept only `{"v":1,"title":<string that sanitizeTitle leaves unchanged>}`. Without the flags the directory is never created. Drop the `key[0..2]` shard (flat dir; at most 500 new files per run).
- B7 (queue and polling): the GET never waits for the model. `pending` = this session's own prompts queued or in flight (once per key). A `null` sanitise result is a miss, not a failure; a normal response resets the failure counter; 3 consecutive transport/HTTP/shape failures or 500 requests -> drain, `pending` 0, generic `error`. Web: refetch when the live session payload changes (not only on session id), abort the in-flight GET on session change/unmount, pause while live updates are paused (LiveContext) or `document.hidden`, resume at once; no edit to `LiveView.tsx`/`live.ts`. Never show a title for an inherited prompt. Router: add `/titles` as its own regex alternative without renumbering existing groups, and test `/map`, `/git`, `/prompts/:n`, `/diff`, `/play` still route.
- B8: `--help`/`--version` still return first; empty `--llm-model` rejected; HELP text documents the flags. Drop the `now?` clock.
