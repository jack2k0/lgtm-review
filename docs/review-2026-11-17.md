# lgtm-review whole-repo audit (main @ bf0e7d0, 2026-11-17)

Auditor: Opus 5.5, effort max, read-only, synthetic inputs only. Probe IDs (`p1`..`p33`) name repro scripts from the audit scratchpad; they are not in the repo. Each slice turns its probes into failing tests first.

Orchestrator re-verification (2026-11-17): p30 (H1), p22 (H3), p10 (H2), p5 (M6, archive part) re-run, all reproduce. The llm-cache half of p5 did not run (server port 1 EACCES), so it is unverified.

Extra (from CI on bf0e7d0, not from the audit): `pnpm audit --audit-level=high` fails both `check` jobs because of a new advisory, GHSA-fc5q-39xc-vjpf. `picomatch` <= 4.0.7 is vulnerable to ReDoS. ## Summary
Strong: the server, export escaping, git discipline, parser robustness, redaction performance. Weak: the status rule (false `checked` from `check && echo OK || echo FAIL`, from edits outside the session dir, and from MCP edits; unanalysed subagent work shown as `checked`/`Skim` in `--summary`) and redaction of derived text (S-32 cut misses high-entropy tokens; whitespace collapsing before redaction defeats the multi-line rules). Locally, turbo replays cached results because root files are not cache inputs.

`pnpm check`: exit 0. eslint 73 warnings, 0 errors. Forced run: core 3354, web 346, cli 792 tests pass.

Counts: Critical 0 · High 4 · Medium 8 · Low 13 · Nit 4.

## Findings
- **H1 (status).** In `check-patterns-classify.ts:624-627`, a failing check followed by a masked exit later in an `&&` chain (`A && B || C`, `A && B; C`) still counts as `checked`. Probes: p30, p31, p33. Fix: the check is unreliable if any later top-level `||`/`;`/newline/`|` follows it. Add fixtures, then run the real-log audit.
- **H2 (status).** An edit in a sibling worktree or another repo counts as covered by a root check, and a check outside the repo counts. Code: `scope.ts:232`, `analyze.ts:449-454`, `scope.ts:44-53`. Probes: p10, p11. Fix: a whole-project check covers only its own tree. Needs an owner decision (FR-017) and the audit.
- **H3 (status).** MCP or other non-built-in edit tools are invisible. Code: `analyze.ts:52` (`EDIT_TOOLS`), `:876`. Probes: p22, p32. Fix: treat write-like tool calls as unknown edits and mark the file list "may be incomplete".
- **H4 (privacy).** S-32 is incomplete: high-entropy tokens keep 39 of 40 characters at cuts (`truncateText` in `parse.ts:198-203`, `trimPartialSecret`, the 20-char window of `cutForDisplay`, `steps.ts:118`, `parse.ts:239`). Probe: p4. Fix: drop a run of 8+ token characters at the cut, and route `truncateText` through `cutForDisplay`.
- **M1 (privacy).** Whitespace is collapsed before redaction, so the newline-dependent rules stop firing. Code: `analyze.ts:1079`, `parse.ts:290,297`, `steps.ts:71`, `summary.ts:66,81,86,143`. Probes: p1, p2, p26. Fix: redact first, collapse at render time.
- **M2 (status).** A false `failing` when a check is piped into grep (`analyze.ts:806-820`). Probe: p27.
- **M3 (status).** A subagent transcript cut by the 5 MB / 20k-event cap still gives `checked` (`subagents.ts:87-95`). Probe: p12.
- **M4 (status/summary).** Unanalysed subagent work after the check is `checked`/Skim; `partial` is ignored by `judge`, `summary.ts:84-85` and `attention.ts:7`. Probes: p25, p25b.
- **M5 (status).** Many test runners are not recognised (rspec, tox, nox, mix, swift, ctest, bazel, mocha, playwright, cypress, phpunit, docker compose exec …). The PRD promises configurable check patterns, and no config exists. Probes: p8, p9.
- **M6 (safety).** S-40 is incomplete: `isInside` in `paths.ts:20-23` treats `<repo>/..arch` as outside, and the archive writes unredacted `.jsonl` into the repo. Probe: p5.
- **M7 (process).** turbo has no `globalDependencies`, so changes to `scripts/`, `tsconfig.base.json` and `copy-web.mjs` do not invalidate the cache. 9 of 10 tasks were cached in the run.
- **M8 (privacy).** Shapes that are not redacted: `.pgpass`, docker `"auth"`, `SSHPASS=`, `ldapsearch -w`, `htpasswd -b`, `dckr_pat_`, pretty-printed `"password":\n "…"`, `?key=`. Probe: p24.
- **L1.** `--list` prints raw ANSI/OSC escape sequences (`format.ts:126-137`). Probe: p20.
- **L2.** A symlinked `--dir` is not realpath'd, so the physical path leaks. Probe: p28.
- **L3.** `--summary` leaves `@mentions` and `#123` live. Probe: p23.
- **L4.** A huge exit code fails the zod schema, and the Steps view breaks (`parse.ts:372-378`). Probe: p6.
- **L5.** Quoted option values (`-t 'adds numbers'`, `-k "a and b"`) are split into bogus scopes (`check-patterns-classify.ts:234-236`). Probe: p18.
- **L6.** No-op and never-fail forms count as passing checks: `eslint --print-config`, `make -q`, `--exit-zero`, node:test `ℹ fail N`. Probes: p7, p9.
- **L7.** `.envrc`, `.env-local` and `.env_prod` are not treated as env files (`redact.ts:32-35`).
- **L8.** The README "Known gaps" section is stale, and "Masked exit codes" over-claims (`packages/cli/README.md:244-250`, `:159`). Probe: p16.
- **L9.** `GATE_CHECK_CMD` silently replaces `pnpm check` (`gate.mjs:932-936`).
- **L10.** Gate tiers: `cli.ts`, `http.ts`, `open.ts`, `core/src/diff.ts`, `pnpm-workspace.yaml`, `turbo.json` and `tsup.config.ts` should be High.
- **L11.** The CI gate runs only on PRs, but main is pushed directly. Release actions are pinned by tag, not by SHA, while holding `NPM_TOKEN`.
- **L12.** A refused archive still exits 0. The export file is written 0644 rather than 0600. Probe: p21.
- **L13.** A scoped pass after a failing full run, with an edit in between, clears the failure silently (`analyze.ts:515-524`). Probe: p17. Owner decision.
- **N1.** The `Story` scaffold in `core/src/index.ts:3-7` is dead.
- **N2.** Duplication: four "analyse all + markInherited" loops, two `isInside` helpers, two `oneLine` functions; `redact.ts` is 1734 lines.
- **N3.** User names under 3 characters and root/user/admin are never redacted; home directories outside `/home` and `/Users` are not mapped to `~`.
- **N4 (unverified).** The legacy `Task` subagent tool name is not matched (`node/subagents.ts:9`).
